# TP-7 capture workflow — 02: catalog and ingestion

Prerequisite: [[TP7-CAPTURE-01]]. Before every task read its execution and experience contracts in `.maestro/playbooks/2026-09-25-TP7-Capture-Workflow/TP7-CAPTURE-01.md`, plus `docs/tp7-capture-workflow.md` and `docs/tp7-capture-ux.md`. Apply the 1–3 file / under-500-line task limit. No real hardware or personal-library access during Auto Run. Next: [[TP7-CAPTURE-03]].

Outcome: durable, verified local originals and an import ledger; the recorder can be disconnected without losing access. Large originals must not pass through a JavaScript array or whole-file AudioBuffer.

## Tasks

- [ ] **02.1 — Implement the native catalog core.** Following the phase-01 schema, add or extend a focused native catalog module under `src-tauri/src/` and its module registration in `main.rs`. Implement versioned load/commit/migration, immutable asset identity, separate source occurrences, and serialized atomic metadata updates. Persist SHA-256, original name, source path/device identity, capture-time provenance, import time, byte size, and probe status. Choose content identity by hash, not filename/size or USB handle. Reject unsupported future schema versions without overwriting them. Completion means the typed API can reopen a catalog, preserve old records, and represent duplicate occurrences without duplicating original bytes.

- [ ] **02.2 — Implement the controlled library-root boundary.** In the catalog module and native command layer, add explicit root selection/opening, path containment, and checked relative-path resolution for originals, metadata, and derived assets. Follow `backup.rs` path/symlink protections; never expose a generic renderer-supplied arbitrary-path read/write command. Handle unavailable/moved roots and insufficient disk space with recoverable errors, not silent creation of an empty replacement library. Completion means runtime access is scoped to the chosen root and automated tests can inject a workspace-local root without opening dialogs.

- [ ] **02.3 — Add streamed TP-7 ingestion.** Extend/reuse `stream_object_to_file` and related native read/hash helpers from `src-tauri/src/backup.rs` through a focused ingestion module. Resolve selected source paths against the current session, stream into uniquely owned staging files, compute hashes, verify final size and persisted bytes, then atomically publish original/catalog records. Surface chunk/file progress and cooperative cancellation; close files and clean up only staging files created by this operation. Every progress and outcome event must identify the single source item it belongs to, so the interface can show it on that row without a global busy state or a modal. Preserve completed imports on partial batch failure. Unchanged filename/size is only a candidate match: do not report a hash-verified duplicate without evidence. Completion means an interrupted read or changed source cannot become a completed asset, while an identical source reimport becomes an occurrence of the existing asset.

- [ ] **02.4 — Add Finder/local-file ingestion through the same pipeline.** Extend the ingestion module and native commands to accept explicitly selected local files, keeping their bytes unchanged and hashing/probing through the same asset/occurrence model as TP-7 imports. Reject directories/path escapes unless directory import was explicitly designed; no recursive scanning of arbitrary user folders. Unsupported audio may be archived with an explicit unplayable status, never silently transcoded. Completion means local and TP-7 inputs produce the same durable records, and cancellation or errors do not discard existing assets.

- [ ] **02.5 — Expose the catalog and ingestion bridge.** Extend `src/utils/tauriBridge.ts` and add a small typed catalog client only if existing abstractions cannot serve it. Match native DTOs and provide open/list/import/per-item-progress/cancel methods, preserving `deviceOperation` and native session protection; importing must not mark the whole workspace busy. Handle browser-only/unavailable-native environments honestly. Do not transport large files or preview payloads as JSON number arrays. Completion means callers can distinguish verified imports, duplicate occurrences, unsupported media, cancellation, and failures without parsing display text, and can attribute each of those outcomes to one item for in-place display.

- [ ] **02.6 — Add catalog and ingestion regression tests.** Add native tests beside the catalog/ingestion modules and bridge tests in `src/test/utils/tauriBridge.test.ts` (split into further test-only tasks if necessary). Cover restart/migration, future schema refusal, concurrent commit serialization, duplicate bytes under different names, same-name different bytes, reused USB handles after reconnect, source truncation, cancellation, disk-full injection, symlink/path traversal, missing roots, and crash recovery between asset publication and catalog commit. All fixture/temp roots must be inside the workspace. Include a streamed source above 128 MB and assert bounded chunk sizes rather than loading it wholesale.

- [ ] **02.7 — Validate ingestion and record evidence.** Run the targeted native/catalog/bridge tests, frontend build, and native offline tests using the current `package.json` commands. Update `docs/tp7-capture-validation.md` with commands, results, the large-file fixture's size/chunk bound, and a restart/reimport result. Fix only phase-02 regressions through separate narrowly scoped tasks if needed. Completion requires that no failed/partial import is labeled verified and no original is overwritten.
