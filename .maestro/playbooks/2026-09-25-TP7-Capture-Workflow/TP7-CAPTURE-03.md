# TP-7 capture workflow — 03: offline sample library

Prerequisite: [[TP7-CAPTURE-02]]. Before every task read the execution and experience contracts in `.maestro/playbooks/2026-09-25-TP7-Capture-Workflow/TP7-CAPTURE-01.md`, the schemas in `docs/tp7-capture-workflow.md`, and the copy, labels, shortcut map and step budget in `docs/tp7-capture-ux.md`. Apply the 1–3 file / under-500-line task limit. Keep the existing preset library intact and usable. Next: [[TP7-CAPTURE-04]].

Outcome: an offline-first sample library that clearly separates device recordings, local originals, and derived clips, and that a musician can use at speed — audition from the list, name without ceremony, find things again later. Use Fieldwork's existing typography/tokens and accessible controls.

## Tasks

- [ ] **03.1 — Implement library query and organization operations.** Extend the phase-02 catalog/client modules with display names, tags, favorites, notes, named collections, and reference-only collection membership for assets and future region records. Distinguish device capture time, import time, and unknown dates. Support stable search/filter/sort and paged or windowed results; search must reach display names, original filenames, tags, notes, and (once phase 04 lands) region names, so one query finds both a take and the clips cut from it. Expose each item's provenance and forward links from the phase-01.2 schema — source device, originating take, outputs that use it — as queryable fields rather than display-only strings. Collection removal must not delete bytes. Preserve original filenames and provenance when changing display names. Completion means metadata and collection edits survive reopen without mutating source files or existing preset-library data.

- [ ] **03.2 — Create the library at a default location and make relocation explicit.** Add a focused setup/state module and panel under `src/components/library/` connected to the phase-02 catalog client. On first run, create and open the library at the documented default location from `docs/tp7-capture-ux.md` without showing a picker, and report where it was created in plain language with a way to change it. Provide explicit Change location and Open existing library actions for users who want a different disk, remembering the last approved root without changing legacy preset storage, and reopen that root on relaunch. A missing, moved, or unreadable root shows an explanation and a reselect action, and validates catalog identity instead of silently starting an empty library. Missing or changed original files remain visible as unavailable; do not silently reassign them by filename, and require a verified expected hash before any explicit relink enables use. Completion means a new user reaches an open, writable library with zero dialogs, while relocation, cancel, reopen, and unavailable-root states all have reachable UI and every test path is injected under the workspace.

- [ ] **03.3 — Build the local sample-library view.** Compose or extend `src/components/library/` patterns (`LibraryFilters.tsx`, `LibraryPagination.tsx`, selection behavior) into a focused capture-library view and stylesheet. Show display name, date with its provenance, duration/channels when known, import/probe status, tags/favorite, original-versus-derived identity, and where the item came from or was sent. Provide search, collection filters, batch metadata actions, sort and scroll/selection that survive leaving and returning, and explicit empty/loading/error/offline states. The empty state must name the two ways in — import from a connected recorder and import files from the Mac — so the view is useful before any device is attached. Auditioning the selected row must be possible from the keyboard per the documented shortcut map without opening an editor, and renaming must be possible inline on the row. After a successful import, point at the next step in the workflow rather than leaving the user on a list of filenames. Do not infer zero duration for unknown metadata. Completion means disconnected users can organize previously imported takes without connecting any device and without reaching for the mouse.

- [ ] **03.4 — Integrate the library into navigation without hiding it on disconnect.** Update `src/utils/teDevices.ts`, `src/components/common/MainTabs.tsx`, and `TabNavigation.tsx` using existing tab registration patterns, adopting the tab label chosen in task 01.4. Keep the new local sample view reachable with no device and with TP-7, OP-XY, or OP-1 Field connected; its label must remain unambiguous against the preset library tab, the on-device recordings/tapes browser, and the Sample lab builder in every device profile. Preserve builder state when switching devices/views and keyboard navigation. Completion means switching device profiles cannot discard or conceal the local capture workflow, and no two visible tabs read as the same thing.

- [ ] **03.5 — Wire the TP-7 import inbox and local import actions.** Extend `src/components/device/DeviceMediaPage.tsx` and the capture-library view/client to select takes and import them via phase-02 commands, with per-row progress, cancel, retry-read, and verified/already-imported/unverified status shown in place. Provide one primary Import new action that preselects the takes not already in the library and states plainly how they were matched and how many will be imported; a fast candidate scan must be labeled as a candidate scan, with hash verification happening during import per the phase-02 contract. Importing must leave search, filtering, preview, and the rest of the app usable, and a mid-batch failure must keep the completed imports and say which items did not finish. Report duplicates as a normal outcome ("already in your library"), not an error. Keep export-originals available. Add native local-file selection to the local view; never auto-import immediately on connection. Completion means imported material can be found in the library after TP-7 disconnect and relaunch, and importing a full card of takes needs one action after connecting.

- [ ] **03.6 — Implement reversible local removal.** Extend the catalog/client and library view with two clearly distinct actions: remove from library, which drops catalog records and leaves audio on disk, and delete audio from the library folder, which is confirmed once, names the file count and bytes, and is refused for anything outside the approved root. Offer a brief undo for removal from the library, and restore metadata, tags, collection membership, and region links on undo. Removal must never touch device content, the legacy preset library, or files outside the library root, and an item referenced by a prepared output or transfer history must say so before it is removed. Completion means a user can prune junk takes without fear and without a file manager, and no removal path can reach data the app does not own.

- [ ] **03.7 — Implement automatic and batch naming.** Extend the catalog/client and library view so every imported take receives a useful default display name derived from its capture timestamp and source folder per `docs/tp7-capture-ux.md`, with the original filename always preserved and visible. Add batch rename over a selection with a documented pattern (base name plus stable numbering), a preview of the resulting names before applying, collision-safe numbering across existing names in the same scope, and undo for the whole batch. Renaming changes display metadata only; it never renames files on disk, never rewrites device content, and never invalidates a rendered region's provenance. Completion means naming twenty takes or regions is a single reviewed operation rather than twenty edits, and no name change can orphan a reference.

- [ ] **03.8 — Add reveal in Finder for library items.** Add a narrowly scoped native command that reveals a catalog-resolved path in Finder, reusing the phase-02 root containment and symlink checks so only paths inside the approved library root can be revealed, and never accepting a renderer-supplied arbitrary path. Wire it to the library view and the library-location panel. Handle unavailable files with the same unavailable state as elsewhere rather than a raw OS error. Do not add a general file-opening or shell-execution capability, and do not weaken the native CSP or expose the command when no library is open. Completion means the user can get from a row to the actual audio file on disk in one action, with the same path safety as every other native file operation.

- [ ] **03.9 — Add library and inbox UI tests.** Create focused component tests for default-location first run with no dialog, relocation and Open existing, reopen, missing/moved roots, relink hash refusal, metadata persistence, unknown/capture/import dates, search across names/tags/notes, filter/sort, collections, batch actions, automatic and batch naming with collisions and undo, remove-from-library undo, delete-audio confirmation and refusal outside the root, reveal-in-Finder containment, import status, per-row progress, cancellation, reconnect, browser-native unavailability, and selection/scroll retention. Assert keyboard audition works from the list and that shortcuts do not fire while a rename field has focus. Extend `MainTabs.test.tsx` or `TabNavigation.test.tsx` for offline reachability, unambiguous labels across device profiles, and focus behavior; assert an import in progress does not make the workspace inert. Use generated catalog/bridge fixtures, not physical hardware. Completion means a cancelled picker/import never produces a success notification and existing preset views still work.

- [ ] **03.10 — Validate the offline organization workflow.** Run the targeted catalog/library/navigation tests and `npm run build`; record evidence in `docs/tp7-capture-validation.md`. Exercise at least 10,000 synthetic catalog entries through the paged/windowed API with a deterministic bound on rendered row count, avoiding fragile wall-clock assertions. Walk the documented import-and-organize path from `docs/tp7-capture-ux.md` against the fixture library and record the actual number of user actions next to the target, noting any step the implementation added. Completion means metadata round-trip, bounded UI rendering, and the recorded step count are all demonstrated; do not claim real-library or hardware performance from fixtures.
