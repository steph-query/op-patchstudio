# TP-7 capture workflow — 04: audition and sample regions

Prerequisite: [[TP7-CAPTURE-03]]. Before every task read the execution and experience contracts in `.maestro/playbooks/2026-09-25-TP7-Capture-Workflow/TP7-CAPTURE-01.md`, the audio/schema decisions in `docs/tp7-capture-workflow.md`, and the shortcut map and naming defaults in `docs/tp7-capture-ux.md`. Apply the 1–3 file / under-500-line limit; split oversized native/audio work before proceeding. No physical devices. Next: [[TP7-CAPTURE-05]].

Outcome: audition long local takes, select a channel/pair, save multiple named regions, and render useful samples without altering the original. Initial editing support is the explicitly documented PCM/float WAV subset; unsupported formats remain exportable as untouched originals with honest UI guidance.

## Tasks

- [ ] **04.1 — Implement bounded local audio reads and metadata probing.** Add a focused native local-audio module and register its commands in `src-tauri/src/main.rs`, reusing the catalog's root/asset resolution. Port/share the validated invariants from `src/utils/wavDecode.ts` and partial-read patterns in `deviceAudio.ts`; do not introduce a permissive competing WAV parser. Return metadata and bounded frame windows by catalog asset ID, checking header/chunk lengths, alignment, channel count, and arithmetic overflow. Explicitly reject unsupported compression/RF64 variants rather than interpreting them as PCM. Completion means a >128 MB source can be probed and a late region read without whole-file IPC or whole-file allocation.

- [ ] **04.2 — Implement incremental waveform peak caching.** Extend the native local-audio module and a focused bridge/client with channel-aware min/max peaks at documented resolutions, indexed by source hash and cache algorithm version. Stream source chunks, publish cache atomically, and support cooperative cancellation with progress. Cache data is disposable; corrupted/stale/missing cache must rebuild without touching originals or catalog metadata. After an import completes, build that asset's peaks in the background so opening a take does not wait on a first-time scan; this work is cancellable, must not block the library or mark the workspace busy, and its absence must never prevent opening a take. Completion means zoomed and whole-take views request bounded peak windows and preserve transient visibility across every supported channel, and a take imported a minute ago opens without a visible build step.

- [ ] **04.3 — Adapt shared waveform display to bounded sources.** Extend/extract `WaveformEditor.tsx` / `EnhancedWaveformEditor.tsx` rendering into a bounded peak-source adapter backed by phase-04.2. Support source-frame coordinates, zoomed peak windows, cursor/selection overlays, and explicit loading/error states without requiring a whole-file AudioBuffer. Keep existing builder input APIs compatible. Completion means an offline long-take waveform can display any selected channel with bounded data and accurately map pointer/keyboard positions back to source frames.

- [ ] **04.4 — Implement bounded local audition transport.** Extend/extract the relevant `useAudioPlayer.ts` transport behavior into a focused bounded-source hook using central `audioContextManager` and local frame-window reads. Implement play/pause, seek, region loop, bounded buffering, error/end states, and disposal/cancellation on source change or unmount. Preserve legacy builder playback semantics and avoid an independent AudioContext lifecycle. Completion means a late region of a long source can play/seek/loop with bounded audio memory and stale reads cannot start playback after navigation.

- [ ] **04.5 — Integrate take audition controls and channel routing.** Compose the bounded waveform adapter and transport in a focused capture-audition component under `src/components/library/`. Add scrub/seek, play/pause, loop controls, and explicit mono/stereo-pair selection, including the final unpaired channel of odd-channel sources. Bind transport and marking to the single shortcut map in `docs/tp7-capture-ux.md`, show each shortcut next to the control it drives, and suppress shortcuts while a text field or numeric input has focus. Show the selected channels consistently in waveform and audio output; no implicit multichannel downmix. Completion means every supported source channel is accessible, the audition loop runs from the keyboard alone, and transport state/errors are keyboard-accessible without modifying source bytes.

- [ ] **04.6 — Implement persistent nondestructive region recipes.** Extend the catalog/client schema with multiple named regions per original, source-frame start/end, channel mapping, gain/fade/normalization options, render version, and original-hash linkage. Add bounded undo/redo for editing and restore persisted regions after relaunch; do not store AudioBuffers in the catalog. Validate half-open frame bounds and distinguish audition-only settings from rendered operations. Completion means editing, duplicating, and organizing regions never modifies the original bytes or loses provenance.

- [ ] **04.7 — Wire region editing into the capture library.** Add a focused region editor view under `src/components/library/` and connect it to the library and capture-audition interface. Provide named regions, numeric start/end plus waveform handles, loop audition, keyboard-accessible editing, channel/pair selection, duplicate-region and delete-region actions, and explicit save/revert actions. New regions receive an automatic name from the parent take and their position per `docs/tp7-capture-ux.md`, so marking never blocks on typing. Offer snap-to-zero-crossing for region edges by reusing `findNearestZeroCrossing` and `applyZeroCrossingToMarkers` from `src/utils/audio.ts` rather than a second implementation: enabled by default for handle drags, visibly toggleable, bounded by the documented search tolerance, and never silently overriding a typed frame value. Show the parent take's regions together with audition so several moments from one recording can be compared in place. Protect unsaved edits on navigation and preserve library scroll/filter state. Completion means one imported take can yield several persisted, individually selectable sample regions without exporting/reimporting through Finder, and cutting a clean-edged clip takes marking rather than manual zero-crossing arithmetic.

- [ ] **04.8 — Implement bounded, deterministic region rendering.** Use native frame-window extraction for the selected region, then compose existing `audio.ts`, `audioExport.ts`, `wavExport.ts`, and `aiffExport.ts` processing where suitable for bounded clips. Render trims and actual fades, optional peak normalization and explicit channel conversion; normalization is opt-in, silence remains finite, and multichannel downmix is never implicit. Apply a documented clip-size/duration bound before allocation, preserving long originals regardless. Verify source identity before publishing a render; changed/missing masters must invalidate caches and block derived success. Track source hash, recipe, output format, sample rate, channels, frames, and rendered hash in derived records. Completion means render and audition share the same recipe semantics; simple untouched extraction preserves source sample values, and transformed output is clearly labeled derived.

- [ ] **04.9 — Split imported multitrack takes into per-track stems natively.** Move stereo-pair extraction for imported assets off the in-memory renderer path currently used by `src/components/device/DeviceMediaPage.tsx` and into the native local-audio module, reusing phase-04.1 frame windows and the catalog's root/asset resolution. Write each pair as a catalog-tracked derived asset or into a user-chosen folder, streaming bounded windows so a long multitrack take is no longer limited by the 128 MB in-memory cap; document whatever bound remains. Preserve sample values, bit depth, and sample rate exactly for untouched extraction, label results derived, record source hash and channel mapping, handle an odd final channel explicitly, and keep the existing device-side stem export working for takes that have not been imported. Name outputs by take and track per `docs/tp7-capture-ux.md`, and report which tracks were written and where. Completion means a full-length TP-7 multitrack take can be split after import without loading the whole file, and the user is never told a take is too large to work with when the bytes are already on the Mac.

- [ ] **04.10 — Add audio, region, and interaction regression tests.** Add focused native tests plus unit/component tests (split into test-only tasks to respect file/line limits). Reuse generated WAV cases from `src/test/utils/deviceAudio.test.ts` and existing audio/export tests. Cover mono/stereo/odd-channel takes, 16/24/32-bit and float cases actually supported, truncated/chunk-padded headers, silent/near-clipping signals, exact region frames, fades, resampled duration/loop endpoints, cache invalidation, undo/redo, source changes, and source hash immutability. Test large-source late-window access and cancellation with deterministic allocation/chunk bounds. Also cover native stem splitting for even and odd channel counts including a source above the old 128 MB cap, zero-crossing snapping within its documented tolerance and its effect on rendered edges, typed frame values that snapping must not override, automatic region naming with collisions, and cancellation of background peak warm-up. Assert keyboard marking and transport shortcuts do not fire while an input has focus. Unsupported formats must produce explicit errors, not plausible-looking corrupted audio.

- [ ] **04.11 — Validate the long-take-to-samples workflow.** Run the targeted native/audio/region tests, existing waveform/audio-player tests, and frontend build. Record fixture sizes, maximum requested window sizes, transform tolerances, output hashes/format checks, the largest take successfully split into stems with the observed chunk bound, and failures in `docs/tp7-capture-validation.md`. Record the actual number of user actions from selecting a take to a saved named region against the step budget in `docs/tp7-capture-ux.md`. Completion means >128 MB masters can be navigated and small regions rendered without increasing the old full-buffer limit or routing an entire take through the renderer. Hardware audio quality claims remain pending manual audition.
